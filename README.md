# FillLab

Windows용 간단한 그림 편집기입니다. 채우기(페인트통) 도구를 중심으로, 기존 프로그램의 동작을 AI 에이전트로 분석한 뒤 **동작 명세만 보고 새로 구현**했습니다. 대학 과제(REA 기반 재개발)로 만들었습니다.

> 이 프로젝트는 Paint.NET과 관련이 없습니다. 원본의 코드, 리소스, 로고, 아이콘, 실행 파일은 사용하지 않았고 저장소에도 포함하지 않았습니다. Paint.NET은 해당 권리자의 상표입니다.

## 대상 앱

| 항목 | 내용 |
|---|---|
| 이름 | Paint.NET (Classic 라이선스) |
| 분석한 버전 | 5.1.12 |
| 실행 관찰한 버전 | 5.2 (두 버전의 동작이 같은지는 확인하지 않음) |
| 출처 | 공식 사이트 getpaint.net에서 설치한 Windows 데스크톱 앱(클로즈드 소스) |
| 주요 기능 | 이미지 열기/저장, 브러시, 채우기(연속/전체, 허용 오차), 사각형 선택과 이동, 실행 취소/다시 실행, 확대/축소 |

## 작업 환경

| 항목 | 내용 |
|---|---|
| OS | Windows |
| 도구 | VS Code 터미널, Node.js, REA(`rea-agents`), Claude Code, Python, Pillow, numpy |
| AI 모델 | Claude Opus 5.5 (Claude Code) |
| 구현 언어 | Python 3 (tkinter, Pillow, numpy) |

## 개발 과정

1. **정적 분석:** REA로 원본을 분석했습니다. 원본을 수정하거나 실행 코드를 재사용하지 않았습니다.
2. **동작 명세:** `docs/SPEC_fill.md`를 만들고 항목마다 확인 / 추측 / 관찰 / UNKNOWN을 구분했습니다.
3. **직접 관찰:** 설치된 프로그램을 사용해 UNKNOWN과 추측을 관찰로 바꿨습니다. 예를 들어 연결이 8방향이라는 점, 허용 오차 경계(검정↔흰색이 83%에서는 제외되고 84%에서 포함), 선택 영역에서의 동작을 확인했습니다.
4. **새 대화에서 구현:** 분석 노트 없이 명세 한 개만 입력으로 구현했습니다. 명세의 빈칸은 `docs/DECISIONS.md`에 기록했습니다.

## 기능 비교와 결과

| 기능 | 원본과 비교 | 구현 결과 | 비고 |
|---|---|---|---|
| 연속 채우기 (8방향) | 대각선 접점도 이어짐 | 성공 | 관찰값대로 구현, 테스트 통과 |
| 전체 채우기 (Shift+클릭) | 같은 색 전체를 채움 | 성공 | 테스트 통과 |
| 허용 오차 | 기본 50%, 검정↔흰색 경계 84% | 부분 성공 | 검정↔흰색만 관찰값과 일치. 다른 색 쌍은 선형 근사 |
| 안티앨리어싱 경계 | 영역 바깥 1픽셀에 옅게 섞임 | 부분 성공 | 관찰한 고정값(26/33/8)을 사용 |
| 선택 영역과 채우기 | 선택 안쪽에서만 동작 | 성공 | 연속 모드로 확인, 전체 모드는 권장대로 구현 |
| 편집 대기와 확정 | 옵션 변경 시 다시 계산 | 성공 | 핸들 모양은 흰 테두리 사각형 |
| 실행 취소/다시 실행 | 한 단계씩 되돌림 | 성공 | 테스트 통과 |
| 브러시, 선택 이동 | (원본 세부 동작 미관찰) | 부분 성공 | 기본 동작만 구현 |
| 이미지 열기/저장 | PNG 중심 | 부분 성공 | 저장은 PNG만 지원 |
| 확대/축소 | 배율 단계 미관찰 | 부분 성공 | 임의 단계로 구현 |
| 샘플링, 선택 품질 옵션 | 옵션이 존재함 | 실패(화면만 구현) | 레이어 기능이 없어 동작에 영향 없음 |
| 이동용 핸들 | 존재함 | 실패(미구현) | 용도를 알 수 없음 |
| 혼합 모드, 해치 무늬 | 목록 미확인 | 부분 성공 | 혼합은 2종, 해치는 4종(추측) |

실패와 부분 성공의 원인은 모두 **추정**이며, 근거는 `docs/DECISIONS.md`의 해당 항목입니다. UI 유사도와 화면별 비교는 아래 데모 영상에서 확인할 수 있습니다.

## UI 유사도

| 구분 | 내용 |
|---|---|
| 비슷하게 맞춘 것 | 위쪽 메뉴 줄과 옵션 바(도구 이름, 도구별 옵션, 확정 버튼), 왼쪽 도구 상자, 기본색/보조색 표시와 교체, 아래쪽 상태 표시줄(이미지 크기, 배율, 안내 문구), 옵션 이름과 기본값 |
| 다른 것 | 도구 아이콘 대신 글자 버튼, 기록·레이어·색상 패널 없음, 색상환 없음, 배경색과 글꼴 |
| 이유 | 원본의 로고, 아이콘, 리소스를 쓰지 않았고, 과제 범위가 채우기 중심이기 때문입니다 |

## 한계

- 허용 오차의 변환 비율은 검정↔흰색 한 쌍의 관찰에서 역산한 근사값입니다.
- 경계 처리는 관찰한 값을 고정해서 쓰므로, 다른 색과 모양에서는 원본과 다를 수 있습니다.
- 분석(5.1.12)과 관찰(5.2)의 버전이 다릅니다.
- REA는 이번 분석에서 메서드 단위의 IL과 메타데이터까지만 제공했고 C# 디컴파일 결과는 얻지 못했습니다. 그래서 세부 로직은 관찰로 보완했습니다.

## 실행

Python 3.10 이상이 필요합니다(tkinter 포함).

```powershell
pip install -r requirements.txt
python src/main.py                     # 빈 이미지로 시작
python src/main.py samples/circle.png  # 이미지를 열고 시작
```

## 시험

```powershell
pip install pytest
python -m pytest -q
```

- `tests/test_acceptance.py`: 명세 9장의 인수 시험 10개
- `tests/test_fill_core.py`: 색 거리, 허용 오차, 8방향 연결, 경계 처리, 합성
- `tests/test_editor.py`: 채우기 흐름(그리기, 편집 대기, 확정), 실행 취소, 브러시, 선택과 이동
- `tests/test_samples.py`: `samples/`의 PNG로 확인하는 [관찰] 항목

## 화면

- **옵션 바(위):** 도구 이름과 그 도구의 옵션이 한 줄로 이어지고, 오른쪽 끝에 확정 버튼이 있습니다.
- **도구 상자(왼쪽):** 채우기, 브러시, 사각형 선택, 선택 이동과 기본색/보조색이 있습니다.
- **상태 표시줄(아래):** 커서 좌표, 이미지 크기, 배율, 마지막 작업이 보입니다.

## 채우기 도구

| 조작 | 동작 |
|---|---|
| 왼쪽 클릭 / 오른쪽 클릭 | 기본색 / 보조색으로 채웁니다 |
| Shift+클릭 | 이번만 전체 이미지 모드로 채웁니다 |
| 누른 채 끌기 | 시작점이 따라 움직이며 결과를 다시 계산합니다 |
| 놓은 뒤 옵션 변경 | 결과를 다시 계산합니다(편집 대기) |
| 시작점 핸들 끌기 | 시작점을 옮깁니다 |
| 다른 곳 클릭 | 이전 결과를 확정하고 새 채우기를 시작합니다 |
| Enter / 확정 버튼 | 확정합니다 |
| Esc | 취소합니다 |

옵션은 다음과 같습니다(괄호 안이 기본값).

| 옵션 | 항목 |
|---|---|
| 방식 | 연속 영역(기본, 8방향 연결), 전체 이미지 |
| 허용 오차 | 0~100% (50%), −/+ 버튼 |
| 알파 | 프리멀티플라이드(기본), 스트레이트 |
| 색 읽기 | 레이어(기본), 이미지 |
| 경계 | 부드럽게(안티앨리어싱 사용, 기본), 또렷하게 |
| 유형 | 단색(기본), 가로줄, 세로줄, 빗금, 격자 |
| 혼합 | 표준(기본), 곱하기 |
| 선택 품질 | 부드럽게(기본), 보통, 빠르게 |

선택 영역이 있으면 채우기와 브러시는 선택 영역 안에서만 동작합니다.

## 명세 표시의 반영

- **[관찰], [확인]:** 명세대로 구현했습니다.
- **[추측]:** 명세대로 구현하고 코드 주석에 "추측"이라고 적었습니다.
- **[UNKNOWN]:** [권장]을 따르거나 가장 단순한 동작을 골랐고, `docs/DECISIONS.md`에 기록했습니다.
